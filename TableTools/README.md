# TableTools

TableTools 是一个 Windows 桌面打表工具，用于递归读取 Excel 表格，按照项目内的表格规则完成解析、合并、校验，并导出客户端/服务器表格数据和客户端 C# 数据代码。

项目以打表功能为核心，其他工具入口暂时保留为占位。本项目不制作安装包或发布版本，直接通过 `run.py` 运行。

## 技术栈

- Python 3.11 及以上版本
- PySide6：桌面 GUI
- openpyxl：读取 `.xlsx`
- xlrd：读取旧版 `.xls`
- 标准库 JSON：配置、表格数据和生成文件清单

字体直接读取当前 Windows 字体，不向项目复制字体文件。

## 环境准备

```powershell
python -m pip install -r requirements.txt
```

支持 Python 3.11 及以上版本。

## 启动

双击项目根目录中的 `启动TableTools.bat` 可以启动。它会优先使用项目内的 `.venv`，只有在依赖缺失时才安装依赖；如果环境不存在，会自动创建环境。启动失败时不要关闭黑色窗口，窗口会直接显示 `tabletools_startup.log` 中的真实错误。

```powershell
python run.py
```

也可以双击 `run.py`：它会检测项目内的 `.venv` 并自动转交给正确的 Python。首次运行或 `.venv` 不存在时，请使用 `启动TableTools.bat`，由启动器创建环境并安装依赖。

程序默认以 1440×960 深色界面启动，支持窗口缩放、白天/晚上/跟随系统主题、简体中文/English，以及侧栏折叠。

## 输入表格

源表放在 `Data` 目录下，工具会递归扫描 `.xlsx` 和 `.xls` 文件，并忽略 `~$` 开头的 Excel 临时文件。

普通表使用固定六行定义区：

```text
第 1 行：table: Skill
第 2 行：字段说明
第 3 行：字段类型
第 4 行：字段名
第 5 行：客户端/服务器标记
第 6 行：默认值
第 7 行开始：数据行
```

单例表在 `table:` 行中使用 `type:single`，通过 `id`、`type`、`data`、`cs` 语义列定义多个配置字段，最终输出为一个包含多个字段键值的配置对象。

同名逻辑表可以分布在多个 Sheet 或多个文件中。这里的 schema 指字段名、字段类型、数组维度、枚举定义和客户端/服务器范围的组合。工具会按 schema 合并为一个逻辑表；只有这些定义完全一致才允许合并。示例表中用 `#` 或 `##` 标记的字段列属于注释列，不会参与 schema 比较。

详细字段类型、数组分隔符、枚举、默认值和错误规则见：

- [表格规则.md](表格规则.md)
- [表格内容规则.md](表格内容规则.md)

## 使用流程

1. 将源 Excel 文件放入 `Data`，子目录会被递归识别。
2. 启动工具，在左侧表列表中勾选源文件。勾选的是文件名，不是逻辑表名。
3. 在右侧切换 Sheet，查看逻辑表名、字段和完整只读数据预览，预览不设置行数上限。
4. 查看“表问题”区域。错误会阻断打表，警告不会阻断。
5. 选择客户端、客户端代码、服务器或服务器代码目标。
6. 点击“打表”。
7. 打表成功后，已勾选的源文件会自动取消勾选。导出目标偏好会继续保存。

源目录会递归监听 Excel 文件变化。文件新增、修改或删除后，工具会在防抖后自动刷新，并尽量保留当前文件、Sheet、筛选和勾选状态。

同名分表和引用表会自动加入当前导出。字段名为 `逻辑表名_id` 时，会按引用关系递归带入目标逻辑表。

## 输出格式

每个逻辑表独立输出一个 JSON 文件。

普通表：

```json
{
  "Rows": [
    {
      "id": 2001,
      "name": "药水",
      "price": 50
    }
  ]
}
```

单例表：

```json
{
  "team_num": 5,
  "team_num1": 5
}
```

JSON 字段名保留源表写法。客户端 C# 文件按逻辑表生成，命名为：

```text
客户端代码/Item_config.cs
客户端代码/GlobalConfig_config.cs
```

生成的 C# 使用 UpperCamelCase 标识符，并通过 `FormerlySerializedAs` 映射源字段名，包装类型面向 Unity `JsonUtility`。

服务器 JSON 会正常生成。服务器代码生成目前仍为 TODO，勾选框处于禁用状态，不会生成虚假的成功文件。

## 配置和生成文件清单

`settings.json` 只保存用户配置、路径、界面状态、筛选条件、最近文件、收藏和最近打表状态。解析缓存写入项目根目录的 `table_data.json`，运行日志写入 `tabletools.log`，两者都可以删除后自动重建。

生成文件清单独立存放在：

```text
%LOCALAPPDATA%\TableTools\GeneratedFiles.json
```

重新导出时，工具只清理清单中同一目标、同一逻辑表和同一文件类型对应的旧生成文件。用户手工放入的文件、未记录文件和其他逻辑表文件不会被删除。

## 当前限制

- 服务器代码生成尚未实现。
- 生成的 Unity C# 尚未在实际 Unity 项目中编译验证。
- 当前示例中 `技能表.xlsx` 的两个 `Skill` Sheet 已按注释列正确合并；`Skill_1` 第 10 行的 `id=asdad` 仍是一个真实的 `int` 类型错误，选择该文件时会显示一个阻断错误并停止导出。修正为整数或删除该行后即可继续导出。
- `schema` 指同名逻辑表的字段名、字段类型、数组维度、枚举定义和客户端/服务器范围。`Skill_1` 与 `Skill_2` 的 schema 一致；第 10 行的问题属于数据值错误。若该行只是测试数据，请在第 1 列写 `##` 让工具按注释行忽略。
- `.xls` 支持依赖 `xlrd`，当前示例目录只包含 `.xlsx` 文件。
