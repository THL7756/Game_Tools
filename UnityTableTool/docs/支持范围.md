# 支持范围

本文区分“表工具的数据能力”和“引擎运行时集成”，避免把通用 JSON 导出误解为已经提供了对应引擎插件。

## 能力矩阵

| 目标 | 表扫描/校验 | JSON 导出 | C# 导出 | 官方运行时包 | 当前结论 |
| --- | --- | --- | --- | --- | --- |
| Unity | 支持（桌面 GUI 与 Unity Editor 工具） | 支持 | 支持，客户端包含 Runtime 适配器 | 支持，`com.company.unity-table-runtime` | 当前完整支持目标 |
| Unreal Engine | 支持 | 支持 | 仅能把生成 C# 当作参考，不能直接作为 UE C++ | 不支持 | 可自行接入 JSON，暂无 UE 专用适配 |
| Godot | 支持 | 支持 | C# 项目可参考数据结构，但没有 Godot 资源导入流程 | 不支持 | 可自行接入 JSON，暂无 Godot 专用适配 |
| 其他引擎/工具 | 支持 | 支持 | 视目标语言而定 | 不支持 | 使用 JSON 作为交换格式 |

## 当前明确支持的输入和数据规则

- 输入：`.xlsx`、`.xls`、`.csv`、`.tsv`；Excel 文件按真实 Sheet 分开读取。
- 表结构：普通表、`type:single` 单例表、同名分表合并、`<表名>_id` 引用检查。
- 类型：基础标量、`enum(...)`、`Vector2/3/4`、`Color`、`Quaternion`、一到三维数组、`localization`、递归 `beans(...)` 和 `map(key)(string)(beans(...))`。
- 输出：GUI 正式流程生成客户端/服务器 JSON 和可选 C#；序列化库还提供 UTB1 `.bytes` 导出 API。

复杂字段使用共享类型 AST 和值解析器。`localization` 查找固定逻辑表 `localization` 的 `id`，`beans` 使用显式 `字段名#类型`，`map` 固定为 key、string、beans 三个分区；解析错误、重复 map key、缺失键和嵌套 `_id` 引用会阻断受影响逻辑表及其反向依赖。

## Unity 支持边界

Unity 包在 `UnityRuntimePackage/com.company.unity-table-runtime`，Runtime 程序集为 `Company.UnityTableRuntime`，Editor 程序集为 `Company.UnityTableTool.Editor`，最低 Unity 版本声明为 `2021.3`。Runtime 可以自动识别 JSON 和 UTB1 bytes，也可以通过 `TableRuntimeSettings.LoadBytes` 接入 `Resources`、Addressables、AssetBundle 或自定义资源系统。Editor 工具可以直接扫描 `.xlsx`、`.xls`、`.csv`、`.tsv`，执行完整表规则校验并导出客户端/服务器数据和代码。

Runtime 不负责 Excel 解析、字段校验、同名表合并或生成 C#；这些工作在桌面 GUI 或 Unity Editor 打表阶段完成。Unity 项目运行时只需要接收客户端输出目录中的数据和客户端 C# 文件。

## UE/Godot 集成边界

UE 和 Godot 当前没有官方插件、代码生成器、资源导入器或运行时缓存协议。可以把 `Data_c` 中的 JSON 作为普通文本资源读取，但表名、主键、字段转换、单例访问和 UI 列表绑定需要由项目自行实现。

后续如果增加官方适配层，应保持 JSON 字段元数据（`fields`、`arraySeparators`、`isSingleton`）的语义一致，并在单独文档中声明各引擎的资源导入和类型映射规则。
