# 问题修复功能补充

本文是 `Data/表格规范.xlsx` 与工具实现的对照记录。附件中的注释列、预览、单例、复杂字段和导出要求已经统一到当前版本；解析、校验、预览、依赖展开、JSON、C# 和 Unity Runtime 复用同一套类型 AST 与值解析器。

## 已落地规则

- 普通表沿用六行定义区，单例表使用 `type:single` 和 `id`、`type`、`data`、`cs` 语义列。
- 字段名为空、字段名以 `##` 开头，或第 1 行对应列以 `##` 开头时，不进入正式字段集合；整行首个单元格以 `##` 开头时，不参与正式校验和导出。
- `#test_`、`#ceshi` 开头的字段或行只校验、不导出。预览仍保留源列、源行和错误定位。
- 正式字段重复生成 `FIELD_NAME_DUPLICATE`，但预览继续显示全部重复列。引用缺失、类型错误和重复 map key 也保留原始列值并单独标红。
- 同名逻辑表的字段名称、顺序、类型、默认值和端标记必须逐列一致；冲突会报告双方坐标并阻止合并。
- 单例表的 `values` 等普通字段只要没有注释标记，就会进入 JSON 的 `data` 对象。

## 复杂字段协议

### `localization`

字段类型为 `localization`，单元格填写键。工具固定从逻辑表 `localization` 的 `id` 列校验键，其他正式列名作为语言代码，例如 `zh_CN`、`en_US`。缺表、缺 `id` 列或缺键都会阻断引用它的表；缺某个语言列不阻断，Runtime 查询不到语言时返回 `null`，键仍保留。

业务表 JSON 只保存键：

```json
{
  "label": "greeting"
}
```

完整翻译只输出到 `localization.json`，每个输出端一份。Runtime 将其以 `"localization"` 加载一次后，通过 `TableManager.GetLocalizationText(key, language)` 使用已有字典索引查询，无需每次遍历。多语言值类型只保存 `Key`，旧对象 JSON 不再支持；升级时需重新导出数据、C# 并更新 Runtime 包。

### `beans(...)`

beans 使用显式字段类型：

```text
beans(item_id#int|count#int)
```

每个子字段必须是唯一、非空的 `字段名#类型`。类型可以是基础类型、数组、enum、localization、嵌套 beans 或 map；以 `_id` 结尾的子字段继续按同名逻辑表主键检查。值按 inner 分隔符解析，嵌套字段通过已知类型递归解析。

JSON 直接输出字段对象：

```json
{ "item_id": 2001, "count": 10 }
```

### `map(...)`

map 固定为三个分区：

```text
map(int)(string)(beans(item_id#int|count#int))
```

单元格按 outer 分隔条目，首个未转义 middle 分隔 key/value，右侧按字符串值和 bean 字段的已知结构解析。示例：

```text
1|文本#2001#10;2|说明#2002#20
```

字符串值需要包含保留分隔符时使用反斜杠。只允许 `\#`、`\|`、`\;` 和 `\\`，其他转义直接报错；同一 map 中重复 key 直接报错。

JSON 使用字符串化 key，值为 `{ "text": "...", "bean": { ... } }`：

```json
{
  "1": { "text": "文本", "bean": { "item_id": 2001, "count": 10 } }
}
```

## 依赖与阻断

选择表时，工具递归发现普通字段、beans/map 内部 `_id` 引用，并自动加入 `localization` 表。校验会递归检查复杂值中的引用、localization key、默认值、数组、enum 和重复 map key。

错误只阻断错误逻辑表及其反向依赖闭包，无关表继续导出；Build 日志会列出阻断集合。缺失引用表仍保留预览列和原始值，不会静默删除。

## 导出与 Runtime

多语言字段在 JSON 中只保存键，beans/map 使用上述结构化格式，其他标量字段保持原有格式。C# 数据类为每个字段生成按字段命名的公开嵌套类型，例如仅包含 `Key` 的 `LocalizationValue`、`ItemNumBean`、`CubeSpecialEntry`；map 字段使用 `Dictionary<TKey, Entry>`。客户端适配器通过 `TableRowView.Read<T>` 读取共享 Runtime 值并转换为这些强类型。

`Data/表格规范.xlsx` 包含基础类型、注释列和行、单例 `values`、localization 表、beans、map、转义字符和 `##cube_special` 注释列回归样例。当前 `dotnet test UnityTableTool.sln -c Release --no-restore` 共 22 个测试，全部通过。
