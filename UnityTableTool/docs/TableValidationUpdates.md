# 配置表检测规则补充

本文记录当前检测、合并和预览使用的规则。

## 单例表

单例表第一行使用 `table: 表名|type:single`，前部语义行包含 `id`、`type`、`data`。解析器会识别目标默认值、说明行和字段数据行；字段数据行允许在字段名前增加说明列，`desc` 只用于说明，不进入输出字段。`values` 是普通字段名，不会被特殊排除；字段名、字段类型和数据值缺失会定位到对应单元格。

## 同名表

同名表按字段顺序合并，正式字段和测试字段分别处理。每个分表的字段数量、名称、顺序、类型、默认值、数组维度、枚举成员和客户端/服务器标记必须一致；冲突会报告双方实际表头坐标并阻止合并。通过检查后，合并输出会保留第一份 schema 的字段顺序，并将有效默认值写入行数据。

## `item_id` 引用

引用字段只使用 `<表名>_id` 格式。检测会确认目标逻辑表存在、引用字段类型与目标主键类型一致，并检查正式行和测试行中的每个非空引用值是否存在于目标表正式数据的主键集合。错误会保留来源文件、Sheet、行、列和字段信息。

## 复杂字段

`localization` 固定从逻辑表 `localization` 的 `id` 列查找键；该表的其他正式列名作为语言代码。`beans(...)` 使用唯一的 `字段名#类型` 子字段声明，`_id` 子字段沿用自动逻辑表引用规则。`map(int)(string)(beans(...))` 的条目以 `;` 分隔，首个未转义 `|` 分隔 key/value，bean 字段按已知字段数从右侧解析。`\\#`、`\\|`、`\\;` 和 `\\\\` 是唯一允许的转义。

复杂类型中的错误只阻断错误逻辑表及其反向依赖闭包。无关表仍可导出，日志会列出阻断集合。JSON、C# 和 Runtime 都复用共享 AST 与值解析器。

## 预览和问题列表

查看表文件时，即使没有勾选，也会检测该文件中全部正式 Sheet、同名分表和递归引用表；未切换到的 Sheet 也会立即更新错误状态。勾选其他文件时，它们的检测结果一并保留。问题列表、统计数字、Sheet 标记和预览高亮使用同一份去重结果。Sheet 标签显示“错”或“警”，悬停显示问题坐标和详情；切换 Sheet 不改变勾选状态。问题来源、Sheet 名和位置使用完整文本，不使用省略号。

同一主键值只在同名逻辑表内判断重复，不同逻辑表允许使用相同 ID。预览按源行、源列定位数据问题，避免重名字段或单例字段共用数据列时高亮其他单元格。

## 界面设置

主窗口的宽度和高度会写入 `ToolData/settings.json`，下次启动时恢复，并始终遵守最小窗口尺寸。
