# 表结构

工具把源文件和逻辑表分成两层：文件层用于列表、收藏、打开和选择；Sheet 层用于详情、逻辑表名和预览。文件名不再作为逻辑表名使用。

普通表每个 Sheet 或表文件使用固定六行定义区：

```text
第 1 行：table: Skill
第 2 行：字段说明
第 3 行：字段类型
第 4 行：字段名
第 5 行：客户端服务器区分
第 6 行：默认值
第 7 行开始：数据行
```

第一行可以包含 `type:single` 元数据：

```text
table: GlobalConfig
type:single
```

单例表使用 `id`、`type`、`data` 语义列识别，`desc` 可选且不导出；列顺序可以调整。源表可以有多行常量字段，每行定义一个字段，所有字段最终聚合成一个单例对象，运行时使用 `GetSingleton`，不要求主键字段。这里的“一条”指输出对象数量，不限制源表只能有一行。

工具递归扫描表根目录下的 `.xlsx`、`.xls`、`.csv`、`.tsv` 文件。示例源表放在 `Data`，输入子目录只用于组织文件，不改变表名规则。

Excel 文件的每个真实 Sheet 都要保留原始名称。详情区上方显示这些 Sheet 标签，切换标签时重新显示对应 Sheet 的 `table:` 逻辑表名、字段和数据。CSV/TSV 文件没有多个 Sheet 时使用文件名作为唯一 Sheet 标签。

字段名为空或以 `##` 开头的列不进入正式输出；以 `#test` 或 `#ceshi` 开头的列参与校验但不导出。数据行首列使用相同标记时，该行不会进入正式输出。

普通表主键默认使用第一个有效字段；重复主键会阻止导出。单例表不要求主键。

数组分隔符按层级固定：

- `int()`：`1#2#3`
- `int()()`：`1#2|3#4`
- `int()()()`：`1|2#3;4|5#6`

`c` 表示客户端，`s` 表示服务器，`cs` 或空值表示客户端和服务器共有。表头仍保留该标记用于选择输出端，但导出的 JSON/bytes 不记录该标记。

同名表可以分布在多个 Sheet 或多个文件中；扫描后按 schema 合并为一张逻辑表，再统一校验和导出。不同 schema 的同名表会报错，不会静默合并。

同名表的正式字段和测试字段都必须逐列保持名称、顺序、类型、默认值和端标记一致。冲突会分别定位到双方实际文件、Sheet、表头行和列。

打表时可以选择只打客户端或只打服务器，结果分别写入 `Data_c` 或 `Data_s`；每个目录内的 JSON 和 bytes 平铺，C# 单独输出到 `Code`，不生成 manifest。
