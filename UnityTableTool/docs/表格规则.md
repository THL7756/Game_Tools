# 表结构

补充：同名表的正式字段和测试字段必须逐列保持名称、顺序、类型、默认值和端标记一致；字段数量或顺序不同也属于 schema 冲突。冲突分别定位到双方实际表头单元格，阻止该逻辑表导出。

源文件和逻辑表分成两层：文件层用于列表、收藏、打开路径和选择；Sheet 层用于详情、逻辑表名和预览。

普通表每个 Sheet 或表文件使用固定六行定义区：

```text
第 1 行第1列：table: Skill（逻辑表名）
第 2 行：字段说明
第 3 行：字段类型
第 4 行：字段名
第 5 行：客户端服务器区分
第 6 行：默认值
第 7 行开始：数据行
```

第 1 行第1列可以包含 `type:single` 元数据来区分是否为单例表：

```text
table: GlobalConfig
type:single
```

单例表使用 `id`、`type`、`data`、`cs` 语义列识别，第三行没有内容则该列不导出；每行定义一个字段，所有字段最终聚合成一个单例对象。数据行允许在字段名前增加说明列，解析器会按字段名、类型、值、端标记的实际位置读取；字段名为 `values` 也按普通字段处理，不会被特殊排除。表格第 4 行没内容不做导出。

工具递归扫描表根目录下的 `.xlsx`、`.xls`、`.csv`、`.tsv` 文件。CSV/TSV 作为单 Sheet 读取，示例源表放在 `Data`。

Excel 文件的每个真实 Sheet 都要保留原始名称。详情区上方显示这些 Sheet 标签，切换标签时重新显示对应 Sheet 的 `table:` 逻辑表名、字段和数据。

字段名为空或以 `##` 开头的列不进入正式输出。第 1 行对应列的单元格以 `##` 开头时，该列整体视为注释列，即使第 4 行有字段名也不进入正式输出。预览使用源列索引保留重复字段和缺失引用字段的位置，并在重复字段列头显示冲突标记。

普通表主键默认使用第一个有效字段；重复主键会阻止导出。单例表不要求主键。

数组分隔符按层级固定：

- `int()`：`1#2#3`
- `int()()`：`1#2|3#4`
- `int()()()`：`1|2#3;4|5#6`

`c` 表示客户端，`s` 表示服务器，`cs` 或空值表示客户端和服务器共有。导出时只会导出各自需要导出的内容。

同名表可以分布在多个 Sheet 或多个文件中；扫描后按 schema 合并为一张逻辑表，再统一校验和导出。正式字段和测试字段分别逐列比较名称、顺序、类型、默认值和端标记；不同 schema 的同名表会报错，不会静默合并。

打表时可以选择只打客户端或只打服务器，结果分别写入各自目录。GUI 当前生成 JSON 和 C#；UTB1 `.bytes` 由序列化库提供，未接入 GUI 开关。

## 示例文件

- `Data/表格规范.xlsx`：普通表、数组、端标记、注释列/行、测试列、`values` 单例表、同名表、localization、beans、map 和常见错误。
- `Data/可识别文件夹里面嵌套的表格/`：递归扫描示例。

首次使用可以直接打开这些文件，再对照根目录 `README.md` 的 Unity 接入示例。
