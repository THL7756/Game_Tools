# 字段规则

补充：`enum(value1|value2)` 的成员由用户自由定义，使用 `|` 分隔；数组分隔符默认使用 `#`、`|`、`;`，也可以在设置中配置为三个互不相同的非空单字符。空文件、空 Sheet、缺少 `table:`、表名为空或定义行不足只记录 INFO，不算正式表。

本文档描述扫描、预览和打表共用的校验规则。工具内容由真实 Sheet、行号、列号和字段名，便于直接回到源表修正。

## 客户端服务器标记

| 标记 | 含义 | 客户端输出 | 服务器输出 |
| --- | --- | --- | --- |
| 空 | 客户端和服务器 | 包含 | 包含 |
| `c` | 客户端 | 包含 | 不包含 |
| `s` | 服务器 | 不包含 | 包含 |
| `cs` | 客户端和服务器 | 包含 | 包含 |

表头标记只决定字段进入哪边导出。

## 注释和测试

- 字段名为空时，该列不进入正式字段集合。
- 字段名以 `##` 开头时，该列是注释/测试列，不参与正式校验和导出。
- 第 1 行对应列的单元格以 `##` 开头时，整列按注释列处理；字段名即使有值也不会进入正式字段集合。
- 整行首个单元格以 `##` 开头时，该行是注释行，不参与正式校验、主键重复检查、引用收集和导出。
- `#test_`、`#ceshi` 开头的字段或行是只校验不导出的测试内容。普通单元格中出现 `##` 不构成注释标记。
- 预览可以显示注释列/行的灰色状态；正式数据和导出只使用同一解析结果中的正式字段、正式行。

## 支持的字段类型

以下类型都必须实际解析，不能把未知类型当作普通字符串放过：

- 基础类型：`int`、`long`、`float`、`double`、`bool`、`string`
- 数组：上述类型的一到三维数组，使用本文档规定的 `#`、`|`、`;` 分隔符；布尔值只接受 `true`、`false`、`1`、`0`。不符合格式时显示红色错误。

- 结构值：`Vector2`、`Vector3`、`Vector4`、`Color`、`Quaternion`
结构值使用逗号分隔的固定分量数量；颜色允许 RGB 或 RGBA 四分量。

- 自定义类型：`enum`，例如 `enum(red|yellow|blue)`。
- 多语言：`localization`，单元格填写语言键，固定从逻辑表 `localization` 的 `id` 列查找。
- Bean：`beans(item_id#int|count#int)`，括号内按 `字段名#类型` 声明子字段，值按 inner 分隔符 `#` 逐项填写。
- Map：`map(int)(string)(beans(item_id#int|count#int))`，三个分区依次是 key、字符串值和 beans 值；单元格按条目 `;`、key/value `|`、bean 子字段 `#` 分隔。
- 复杂类型支持递归嵌套。类型表达式使用括号深度解析，不能使用未配对括号或重复 bean 字段名。

## 字段名特殊逻辑
若字段名为`逻辑表名_id`那么这里相当于是调用这张逻辑表的id。

引用目标不存在时仍保留源字段和原始单元格值，预览将引用问题标红；缺失引用属于阻断错误，不能静默删除该列或回退为普通字符串。

## 数组类型

```text
int()       -> 1#2#3
int()()     -> 1#2|3#4
int()()()   -> 1|2#3;4|5#6
```

一维使用 `#`，二维外层使用 `|`、内层使用 `#`，三维外层使用 `;`、中层使用 `|`、内层使用 `#`。最多三维，支持用户设置三个单字符分隔符。复杂值中需要保留分隔符时使用 `\#`、`\|`、`\;` 和 `\\`；其他反斜杠转义直接报错。数组元素仍使用基础标量和结构值规则校验；空元素、错误层级分隔符和超过三维都属于错误。

## 复杂字段值

`localization` 的值是键。工具校验键必须存在于逻辑表 `localization`，该表固定使用 `id` 作为键列，其他列名就是语言代码，例如 `zh-CN` 和 `en-US`。缺少某个语言列不阻断导出，Runtime 查询不到语言时返回空文本并保留键。

`beans(...)` 的每个子字段必须写成 `字段名#类型`。子字段也可以是数组、enum、localization、嵌套 beans 或 map；子字段名以 `_id` 结尾时自动引用同名逻辑表的主键。

`map(keyType)(string)(beans(...))` 固定要求三个分区，数据示例为 `1|文本#2001#10;2|说明#2002#20`。`;` 分条目，首个未转义 `|` 分 key/value，右侧按 bean 字段数量从后向前解析。Map key 必须唯一。Map 中的字符串值允许用反斜杠转义保留分隔符。

复杂类型导出为结构化 JSON。`localization` 输出 `key` 和 `translations`，`beans` 输出字段对象，`map` 输出以字符串化 key 为属性名、值为 `{text, bean}` 的对象。

## 单例表

第 1 行第1列使用 `type:single` 标记。前几行包含 `id`、`type`、`data`、`cs` 的语义行决定字段位置。多行常量字段会聚合为一个输出对象，不要求主键。

单例数据行可以带说明列，字段名、类型、值和端标记按语义列读取。`values` 是普通字段名，不得在解析、预览或导出时硬编码排除；示例工作簿中的 `values: int()` 必须出现在单例 JSON 的 `data` 对象中。

单例表仍执行字段类型、数组、默认值、结构值和数据行数量校验。`int` 字段填写字符串、默认值类型错误或结构值分量数量不正确，都必须在检测结果中显示红色错误。

## 严重级别

- 错误（红色）：字段类型/默认值/数组分隔符/主键缺失或重复、单例行数、引用目标缺失、Sheet 或文件结构无法读取等会阻断导出的规则；引用的逻辑表id未找到。
- 警告（黄色）：不会改变导出结果但需要提醒的情况可选，非阻断的目录提示。
- 信息：仅用于状态记录，不计入错误和警告统计。

错误/警告格式示例
角色配置.xlsx · Sheet1 · 第7行 · description 字段 · 问题：字段为空

## 重复字段和同名表 schema

预览字段以源列身份（字段定义行、源列索引）作为唯一键，不以字段名作为字典键。正式字段重名时，两列都继续显示，列头显示重复提示，并为每个冲突位置生成 `FIELD_NAME_DUPLICATE` 错误；错误会阻断导出。

同名逻辑表合并前，正式字段和测试字段都必须逐列比较名称、顺序、类型、默认值和客户端/服务器标记。字段数量、顺序或任一属性不同都生成双方定位错误，不能按字段名静默并集。

## 表列表和打表

表列表按文件名展示，搜索框可以叠加“收藏”“最近 10 张”“所有表”筛选。一个文件只显示一行，文件详情中的 Sheet 标签来自实际读取结果；当前选中的 Sheet 决定详情标题、逻辑表名和完整预览数据，预览不限制行数。分表和关联表会自动加入当前导出。客户端、服务器可以分别或同时导出，结果写入 `客户端表格数据`、`服务器表格数据`，代码写入 `服务器代码`、`客户端代码`。导出成功后自动取消勾选。
